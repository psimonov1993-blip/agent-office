# Подключение своих инструментов

Офис читает файлы; ни сетевого API, ни доступа к вашим моделям у него нет. Если инструмент не пишет поддерживаемый журнал, добавьте небольшой адаптер, который обновляет JSON состояния.

## JSON одного агента

Минимальный формат:

```json
{
  "status": "editing",
  "event_at": "2026-11-25T12:00:00Z"
}
```

Это пример с фиксированным временем. Ваш адаптер должен записывать реальное время события в ISO 8601; лучше UTC с `Z`. Обновляйте файл при действительных событиях. Не обновляйте время рабочей активности таймером, если подтверждений работы нет.

Допустимые значения `status`: `reading`, `editing`, `running`, `working`, `checking`, `waiting`, `assigned`, `done`, `error`, `unknown`, `stale`.

Имя, роль и подпись задачи задаются в конфигурации офиса. Дополнительные поля JSON игнорируются. Размер исходного JSON ограничен 64 КБ. Записывайте его атомарно: временный файл в той же папке, затем замена конечного файла.

Выберите этот файл кнопкой **«Другой агент (JSON)»**. Не выбирайте его напрямую в браузере: браузеру нужен общий снимок `.runtime/agent-office.json`.

Пример конфигурации:

```json
{
  "version": 1,
  "sources": [
    {
      "id": "writer",
      "name": "Редактор",
      "role": "Тексты",
      "task": "Статья для сайта",
      "kind": "state",
      "path": "./my-agent-status.json"
    }
  ]
}
```

ID уникален, до 20 латинских букв, цифр, `-` и `_`. До 6 источников. Один файл нельзя подключить дважды. Относительный путь считается от конфигурации, `~/` — от домашней папки. При отсутствии файла остальные источники продолжают работать.

## Codex и Claude

`kind: "codex"` и `kind: "claude"` читают ограниченный хвост выбранного `.jsonl`. Списки распознаваемых инструментов находятся в `observer.py`; неизвестные инструменты отображаются как общая активность.

Для Codex используются события `response_item` и `event_msg`, для Claude — `assistant` с `tool_use` и `system` с `turn_duration`. Внутренний формат и местоположение журналов могут измениться. Адаптеры тестируются на синтетических примерах этих форматов. Совместимость с каждой версией приложений не гарантируется.

При `helpers: true` (по умолчанию) наблюдатель сопоставляет поддерживаемые вызовы/ответы `collaboration` в журнале Codex. Помощники занимают оставшиеся свободные места после основных источников. Для каждого источника ведётся отдельная ограниченная память процесса, поэтому одинаковые имена помощников из разных сессий не смешиваются. Тексты поручений и отчётов не переносятся. Скрытое количество доступно в `observer.hidden_helpers` выходного JSON.

## Общий снимок для стороннего адаптера

Можно обойти Python-наблюдатель и самостоятельно формировать файл для страницы:

```json
{
  "schema_version": 1,
  "generated_at": "2026-11-25T12:00:00Z",
  "agents": [
    {
      "id": "writer",
      "name": "Редактор",
      "role": "Тексты",
      "task": "Статья для сайта",
      "status": "editing",
      "event_at": "2026-11-25T12:00:00Z",
      "source": "custom_state"
    }
  ],
  "events": [],
  "observer": {"mode": "read_only"}
}
```

В этом случае выберите свой общий снимок кнопкой «Подключить живые данные». `generated_at` — время формирования снимка, `event_at` — время последнего события конкретного агента. Это разные вещи. Чтобы проверить сохранённый пример, используйте «Открыть снимок»: движение там выключено.

Файл для браузера ограничен 1 МБ, ID — до 32 символов, сцена — до 6 агентов. Названия и подписи выводятся как текст. Не включайте в общий снимок секреты и переписку.
